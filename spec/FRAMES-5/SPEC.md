# FRAMES-5: Text layout

Status: accepted

## Summary

Text is laid out by resolve with real fonts: the face chosen by family, weight and style, a title's runs styled, tracking, kerning, OpenType features and baseline shift, lines broken and wrapped, runs shaped by the shaping provider, line limits, and the characters, words and lines laid out text is split into, with where each character lies.

## Motivation

If renderers laid out text, the same title would wrap differently on each, a lower third would end at a different place on each, and a frame measured from its content would not match what is drawn. Resolve writes glyph runs, so every renderer draws the same lines. A title often mixes looks inside one paragraph (a name in bold and a role in regular weight, one word in another colour), and runs give that as data, each in a named style, without a markup syntax to escape.

## Rules

Text is laid out by resolve, with real fonts, so line breaks, faces, glyphs and every title's box are part of the resolved document and are the same on every renderer. Where a title's tracking, line height or background takes keyframes, evaluation places its glyphs and lines and sizes its box at each instant from that layout ([Spacing](#spacing), [Lines](#lines)).

### Runs

A title's text ([FRAMES-11](../FRAMES-11/SPEC.md)) is a string or a list of runs:

```json
"title": [ { "text": "Ana Ruiz", "style": "name" }, { "text": "\nDirector of photography", "style": "role" } ]
```

- A string is one run in the clip's `style`.
- A run is `{text, style}`. `text` is a string. `style` names a theme text style ([FRAMES-22](../FRAMES-22/SPEC.md)) and is optional: without it the run is in the clip's `style`. A style a run names that the theme in effect does not hold stops.
- A run's style gives that run its character attributes: `font`, `size`, `weight`, `italic`, `tracking`, `kerning`, `features`, `baselineShift`, `color`, `stroke`, `highlight` and `underline` ([FRAMES-22](../FRAMES-22/SPEC.md), [below](#highlights-and-underlines)), with the title's `character` merged over them ([FRAMES-11](../FRAMES-11/SPEC.md)). Every other attribute is a paragraph attribute and comes from the clip's `style`, with the title's `paragraph` merged over its `align`, `lineHeight` and `background` ([FRAMES-11](../FRAMES-11/SPEC.md)): `placement`, `offset`, `align`, `lineHeight`, `lines` and `background`. A run style's paragraph attributes are not read.
- The runs are laid out as one text, in order. A run's text may hold `\n`, and a line may hold parts of several runs.
- **A grapheme cluster (an extended grapheme cluster of UAX #29) is never split over runs**, since a character set in two styles is no one character: a cluster that a run boundary falls inside takes the style of the run its first scalar is in, and its later scalars are set and shaped with that run.
- An empty list of runs stops, since it is a title with nothing to show.

### Faces

- A style's family is the first family in its `font` list, or in the theme `font` when it has none, that its pack carries ([FRAMES-17](../FRAMES-17/SPEC.md)) or the machine has installed. A list with no family on the machine stops, naming the families.
- Its face is chosen among that family's faces by the font matching of CSS Fonts 4, with `font-stretch: normal`, the style's `italic` as `font-style` and its `weight` as `font-weight`. Width is narrowed first: the faces of normal width, else the narrower ones from the widest down, else the wider ones from the narrowest up. Then style: for `italic`, italic faces, else oblique ones, else upright ones; otherwise upright faces, else oblique, else italic. Then weight: a weight from 400 to 500 takes the nearest face from it up to 500, else the nearest below it, else the nearest above 500; a lighter weight takes the nearest at or below it, else the nearest above; a heavier one the nearest at or above it, else the nearest below. A face's width, style and weight are those its font file declares in its OS/2 table, as CSS reads them. So a family without a 300 face sets `light` text in its regular face, as a browser does.
- `italic: true` in a family with neither an italic nor an oblique face is set in its upright face, as the matching above gives it and a browser sets it. frames synthesises no weight and no slant, as CSS `font-synthesis: none`.
- Characters the face lacks fall back as CSS falls back: to the later families of the style's `font` list in order, each face chosen by the matching above, and then to a face the shaping provider finds on the machine for the style's weight and italic. The resolved document keeps the face it found, as it keeps recognised text ([FRAMES-21](../FRAMES-21/SPEC.md)).
- **A fallback face is chosen for each grapheme cluster, never for part of one**: a cluster is set in the first of those faces that has every scalar of it, and one that none of them has whole in the face the shaping provider finds for it. So a combining mark the face lacks takes its base letter to the face that has both, and no cluster is split over faces.
- **Fonts are part of the environment the resolved document pins** ([FRAMES-19](../FRAMES-19/SPEC.md)): every face resolve set text in, fallback faces included, is written with its hash, so text that fits a title's `width` and `lines` with the fonts it was resolved with is laid out and drawn the same on every machine it is rendered on. Resolved on a machine with other fonts, the same text is laid out with those, and it may take other lines or stop on `lines`, which is why a pack ships the fonts its templates are designed in ([FRAMES-17](../FRAMES-17/SPEC.md)).

### Spacing

- Resolve shapes each run with its style's `features`, and with the OpenType `kern` feature on for `kerning: metrics` and off for `kerning: none`. A feature the style does not set is as the font's script turns it on or off, as CSS leaves it. A feature tag the face does not have does nothing, as in CSS.
- In a run whose `tracking` is not 0 at some instant the optional ligatures (`liga`, `clig`, `dlig`) are off, unless its `features` turns them on, as CSS turns them off under `letter-spacing`, since a ligature would join characters the tracking spaces apart.
- The shaping provider gives each glyph an advance, which moves the pen along the line, and a placement offset from the pen, as a font's GPOS table places a combining mark over its base. A glyph is drawn at the pen position with its placement offset added, and the pen moves by advances and tracking alone, so a placement offset moves the glyph it is on and nothing after it.
- `tracking` adds `tracking / 1000 ×` the run's size after every character of the run that has glyphs of its own ([Units](#units)), except the last on each line, and a character with none adds none, so a ligature that tracking leaves on, a required one such as `rlig` or one the `features` turn on, is followed by one tracking. The tracking after a character is space between the pen position where its glyphs' advances end and the one where the next character's glyphs begin, which belongs to no character: the shaping provider gives advances without tracking, and resolve adds it to the pen, never to an advance. So the width of a line, which wrapping and `align` measure, holds the tracking between its characters and none after the last one, and tracking does not move a centred or right-aligned line off its place.
- **Keyframed `tracking` ([FRAMES-11](../FRAMES-11/SPEC.md)) keeps the line breaks resolve makes once**, since letter spacing that opens or closes is a standard title move, and outside frames it would be a title for every frame ([FRAMES-25](../FRAMES-25/SPEC.md)), while broken once at its widest the lines hold at every value it takes. **The lines are broken once for the whole motion, at the widest tracking it takes**, since the design a title draws is its motion as well as its rest: one line layout holds the whole clip, and no instant overflows it. Keyframed tracking comes only from the title's `character`, one timed value over every run, so its keyframes and eases are every run's and every run reaches its widest at the same instant. A `null` in those keyframes is each run's own tracking ([FRAMES-4](../FRAMES-4/SPEC.md)), and where the runs' own trackings lie on both sides of a keyframe's value their widest instants differ; each run is still broken at its own widest, which no instant passes. Resolve breaks the lines with each run at the largest tracking it takes over the clip's visible range, an ease's overshoot included, which the formulas of its eases give exactly ([FRAMES-4](../FRAMES-4/SPEC.md)), so no line is wider than `width` at any instant, and checks `lines` there. It places each glyph at the run's static tracking, its style's with the title's static `character` merged over it. At each instant evaluation places every glyph along its line, moved by the tracking added after each character with glyphs of its own before it on that line beyond the static tracking (the run's tracking at that instant less its static tracking, `/ 1000 ×` the run's size, for each such character), and places each line again by `align` on its width at that instant. A title without `width` then has a text box as wide as its widest line at that instant, which keeps its left edge, its centre or its right edge where resolve placed it, as its `align` says, so its anchor point and its position stay. So a tracking that bounces past its last keyframe bounces in full, and no line widens past the width it was broken at. Highlight and underline pieces run over their glyphs where they are at that instant, a character's glyph box ([Units](#units)) moves as its glyphs move and keeps its width, and a unit's glyph box, its box and its parts move and widen with their glyphs.
- `baselineShift` raises the run's glyphs by its length above the line's baseline, and lowers them when it is negative. Lines keep their spacing and the text box its size: a line's ascent and descent are those of its runs as if unshifted, so a raised run may reach outside the text box. It may take keyframes, and evaluation raises the glyphs and their characters' glyph boxes ([Units](#units)) by its value at each instant ([FRAMES-11](../FRAMES-11/SPEC.md)).

### Lines

- Lines break by Unicode line breaking (UAX #14) over the text of all runs together, at the title's `width` when it has one and at every `\n`. A title without `width` breaks only at `\n`, so each of its lines is as long as its text. A run boundary is not a break opportunity of its own. Words are kept whole as CSS `word-break: keep-all` keeps them: no line breaks between two letters, digits, ideographs or Hangul syllables, so Korean breaks at spaces and `iPhone에서` stays whole, and Chinese and Japanese also break only at spaces, punctuation and the other places UAX #14 gives outside those pairs. A word wider than `width` starts a line of its own and breaks inside where UAX #14 allows, unless its style keeps it on one line. A piece of it that still has no break opportunity stays whole on its line and widens the text box to hold it.
- The spaces that end a line hang past its end: they are not part of its width, so wrapping and `align` do not measure them, and they stay where they were set. A space is a grapheme cluster whose first Unicode scalar has the Unicode `White_Space` property, whatever follows that scalar in it, so a space that carries a combining mark is a space. The `\n` that ends a line is set on no line.
- Lines are `lineHeight` apart, baseline to baseline, the clip style's with the title's `paragraph` merged over it. The glyphs of every run on a line share its baseline. The first baseline lies the largest ascent among that line's runs below the top of the text box, and the box ends the largest descent among the last line's runs below the last baseline. A line with no text, which only a `\n` makes, takes the ascent and descent of the run it begins in. A `\n` that ends the text starts such a line after it, as every `\n` starts a line, so `"Hello\n"` is two lines, the second empty, and counts as two against `lines`.
- **`lineHeight` may take keyframes in the title's `paragraph`** ([FRAMES-11](../FRAMES-11/SPEC.md)), since no line break depends on it: lines break across the width alone. Resolve places the lines at its static value, the clip style's with the title's static `paragraph` merged over it, and at each instant evaluation places them at its value then: the first baseline stays, and each later line moves by the change in line height once for each line before it. The text box keeps its top edge where resolve placed it, so its anchor point and its position stay and the lines below the first move down as they open, as After Effects moves the lines of a text layer when its leading changes. Highlight and underline pieces, glyph boxes ([Units](#units)), units' boxes and their parts move with their lines.
- The text box is as tall as its lines at each instant. A title with `width` has a text box `width` wide, and a title without one has a text box as wide as its widest line, which fits the text exactly. The paragraph background, the clip style's `background` with the title's `paragraph` merged over it, lies behind the text box and grows the title's box by its padding on each side. Its `color`, `padding` and `radius` may take keyframes, and at each instant it is drawn, and grows the title's box, with their values then.
- Each line is placed inside the text box by its `align`, the clip style's with the title's `paragraph` merged over it, measured on the advances of all its runs: inside `width` when the title has one, and inside the widest line when it has none.
- Resolve shapes each run of text with the shaping provider, which gives glyph ids, advances and placement offsets ([Spacing](#spacing)), and a run boundary ends a shaping run. frames breaks, wraps and places the lines. The resolved document carries glyph runs (font file, face, size, colour, stroke, highlight and underline pieces, glyph ids and positions) and the box they fill. A renderer draws the glyphs where they are written and shapes nothing.
- A style's `lines` is the most lines its text may take, a whole number of 1 or more. It limits a title with `width` or without one. Text that needs more lines than that, after wrapping at `width` and after every `\n`, stops, since cutting it or shrinking it to fit would show something other than what was written; a title without `width` counts the lines its `\n` make. So a line of a `lines: 1` style that is wider than the title's `width` stops, since it would need a second line. Without `lines` a title takes as many lines as it needs.

### Highlights and underlines

A run's highlight and its underline mark the run where it lies, as a highlighter and an underline do on a page. They are drawn on each line the run occupies, as one piece per line, each piece with its own padding and rounded corners, as CSS `box-decoration-break: clone` draws an inline box broken over lines.

- A piece spans the run's glyphs on that line, from the origin of the first to the end of the advance of the last, the glyphs a fallback face set included and the spaces that end a line excluded. Spaces inside the run are in it.
- A highlight piece runs from the run's ascent above the baseline to its descent below it, the ascent and descent of its face at its size, as CSS paints an inline box's content area. It grows by its `padding`, vertically above and below and horizontally at both ends, and its corners are rounded by its `radius` ([FRAMES-20](../FRAMES-20/SPEC.md)).
- An underline piece is a band across the piece, without padding, `width` thick, its top edge `offset` below the baseline, in its `color`. A `true` underline takes the leaves below it, and a key that no layer gives takes the thickness and the position of the top edge from the face's `post` table at the run's size, and the run's colour ([FRAMES-22](../FRAMES-22/SPEC.md)). It is drawn through descenders, as CSS `text-decoration-skip-ink: none` draws it.
- Both move with the run's `baselineShift` at each instant. A highlight's `padding` and `radius` and an underline's `width` and `offset` may take keyframes ([FRAMES-11](../FRAMES-11/SPEC.md)), and each piece is drawn with their values at each instant.
- Neither takes part in layout: they move no glyph, add no space and do not grow the text box, so a padded highlight may reach over the space beside its run and out of the text box. A title's drawn extent holds them ([FRAMES-6](../FRAMES-6/SPEC.md), [FRAMES-14](../FRAMES-14/SPEC.md)).
- They are drawn over the paragraph background and under every glyph: the highlights in text order, then the underlines, then the glyphs' strokes and fills ([FRAMES-20](../FRAMES-20/SPEC.md)).

### Units

A title's laid out text is split into characters, words and lines, in reading order, which is the order of its text. `evaluate` reports them and where each character lies at an instant ([FRAMES-23](../FRAMES-23/SPEC.md)), and a title whose animation plays by character, word or line ([FRAMES-14](../FRAMES-14/SPEC.md)) moves them as its units.

| Name | Meaning |
| --- | --- |
| `character` | an extended grapheme cluster of UAX #29 |
| `word` | a word between UAX #29 word boundaries, with the punctuation it touches |
| `line` | a laid out line |

- A line's characters are its grapheme clusters up to the last one that is not a space, the spaces inside it included. The spaces that hang past its end ([Lines](#lines)) are no character, and a line that holds nothing but spaces, such as an empty line a `\n` makes, has none.
- A piece of text between two UAX #29 word boundaries that holds a letter, a digit or an ideograph is a word. A piece of punctuation or symbols joins the word it touches with no space between them, the word before it when it touches two, so `Hello,` and `"Quote"` are one word each, and a dash between two spaces is a word of its own. The boundaries are those of UAX #29's default rules, with no dictionary, so each Chinese or Japanese ideograph is a word, a Korean word runs from space to space, and `iPhone에서` is one word. A space is in no word. A word is the word as written: one a line breaks inside ([Lines](#lines)) is still one word.
- **Glyphs are assigned to characters by one rule**, which covers ligatures and the scripts whose shaping moves a glyph across characters, as Devanagari moves a reph or a pre-base form. The shaping provider gives each glyph the scalar of the text it was set from ([FRAMES-21](../FRAMES-21/SPEC.md)), and each glyph is taken with the character that scalar is in. A line's glyphs, in their order, are cut into groups where that character changes, and neighbouring groups are merged until every character of a group comes before every character of the next, so the groups lie in increasing text order. A group holds the characters from its first up to the next group's first, the first group of a line from the line's first character, and its glyphs belong to its first character. Every later character of a group has no glyph of its own: its glyph count and its advance are 0 and it shares the glyph box of the group's first character. A ligature is the case of one glyph, as `ffi` sets three characters in one glyph in `office`, and a character is never joined to another.
- Each character, word and line has a range of the title's text, `[start, end)` counted in Unicode scalars over the title's text, the text of its runs joined in order ([Runs](#runs)). A character's range and a word's hold their scalars. A line's range runs from the start of its first character's range to the end of its last one's, and a line with no character has the empty range where it starts: at the first scalar set on it, or, for a line nothing is set on, at the scalar after the `\n` before it. So the spaces that hang past a line's end and the `\n` that ends it are in no line's range.
- **Where text lies is a fact of its characters and its lines.** A character's glyph box is a fact of the pen, not of where its glyphs are drawn: it starts at the pen position where its glyphs begin on its line and is as wide as the sum of their advances, whatever placement offsets they are drawn with, the tracking after it left out ([Spacing](#spacing)). It runs down its line from its baseline less the line's ascent to its baseline plus the line's descent, the largest ascent and descent among the line's runs, and its baseline is the line's baseline raised by its run's `baselineShift`. A character with no glyph of its own has the glyph box of its group's first character, so the characters of a ligature share its box. A line has one place whatever units animate its characters: its baseline, unshifted, and its ascent and descent ([Lines](#lines)), so a line with no character has a place too. A word lies where its characters lie and has no place of its own. Glyph boxes and lines lie in the text box, and at each instant a character's glyph box is its box at the static values moved as its glyphs move then, and a line lies at its baseline then ([Spacing](#spacing), [Lines](#lines)), so a character's box is the same for the same drawn glyphs whether the tracking takes keyframes or not.

Under `by`, the units are the title's characters, words or lines, in reading order, except that:

- Spaces are not units and belong to none: a `line` unit holds its line's characters but its spaces, and a line that holds nothing but spaces is no `line` unit.
- A unit does not cross a line: under `word`, a word a line breaks inside is a unit on each line.
- Under `word`, a character that is neither a space nor in a word, such as a word joiner (U+2060) between two spaces, is part of the unit before it on its line, or of the next when none is before it, as a piece of spaces is part of a unit (below).
- Units that would share a group of glyphs (above) are one unit. Under `character` the optional ligatures (`liga`, `clig`, `dlig`) are off, unless the style's `features` turns them on, so that each character can move alone.
- A unit's glyph box runs across its glyphs, from the origin of the first to the end of the advance of the last, and down its line, from the line's baseline less the largest ascent among the line's runs to the baseline plus their largest descent. A unit's box is its glyph box grown on every side by half the widest stroke among its glyphs, and then to hold the parts of highlights and underlines it carries (below) at the largest padding, underline `width` and `offset` their keyframes give. Both are in the title's box, and do not move with `baselineShift`, so the units of a line that carry no highlight share the line's height and its centre.
- The paragraph background is not part of any unit. A run's highlight and underline are drawn with the units whose glyphs they mark, so they enter and leave with their words. Each piece ([Highlights and underlines](#highlights-and-underlines)) is cut into parts, one for each unit with a glyph in it, at the origin of the first glyph of every unit after the first: a unit's part runs over its glyphs and the spaces after them inside the piece, and the first and the last part reach to the piece's ends, its padding included. A part is the piece as drawn whole, with its padding and rounded corners, cut to the part's span across the line, so once every unit has entered and before any leaves, the title draws as it does without `by`, at any opacity, blend, mask or track matte of the title, since its units are composited as one group ([FRAMES-20](../FRAMES-20/SPEC.md)). A piece that holds no unit's glyph, only spaces, is part of the unit before it on its line, or of the line's first unit when none is before it, so a part stays on its line; on a line with no unit it is part of the unit before it in reading order, or of the title's first unit. So every piece is drawn by a unit, and a title by unit at rest draws as it does without `by`.

## Interactions

Styles are [FRAMES-22](../FRAMES-22/SPEC.md). A title's keys, `width` among them, are [FRAMES-11](../FRAMES-11/SPEC.md). The shaping provider is [FRAMES-21](../FRAMES-21/SPEC.md). Pack fonts are found as [FRAMES-17](../FRAMES-17/SPEC.md) says. A title's box is measured into a content-fit frame as [FRAMES-6](../FRAMES-6/SPEC.md) says.

## Alternatives considered

Inline markup (Markdown's `**...**`, a subset of HTML): it needs an escape for its own characters, it reaches only the looks its syntax names, and an agent writing text from a transcript or a script would have to quote it. Runs name any theme style and hold text as it is.

A default `width` taken from the frame: a title's box would change with the frame it is drawn on, a background could not hug a short title without its own `width`, and a content-fit frame has no width yet to take it from. A title without `width` is point text and a title with it is paragraph text, as After Effects makes them.

Highlights and underlines that take space, as CSS padding on an inline box widens its line: a highlight added to one word would rewrap the paragraph and move every word after it, where an editor adds a highlight to a caption that is already timed and placed.

Paragraph attributes per run (a run with its own alignment or line height): one paragraph has one alignment and one line spacing in every NLE title tool, and a second paragraph that needs another look is a second title. A title sets its own over its style's through `paragraph`, as After Effects' Paragraph panel sets them on a text layer.

Synthesised bold and slanted italic, as CSS `font-synthesis` and After Effects' Faux Bold and Faux Italic make them: a renderer would have to embolden or shear outlines its font does not hold, and two renderers would draw them differently. A family's own faces are what a type designer drew, and a style that asks for a slant its family cannot give is set upright, as CSS sets it under `font-synthesis: none`.

Optical kerning, as After Effects and InDesign offer it: it is each tool's own algorithm, with no formula two implementations could share. `metrics` is the font's own kerning, which every shaper reads the same.

Lines broken at the static tracking, the title stopping where any instant of a keyframed tracking overflows `width`: a name that fits at rest and overflows during a tracking-in entrance would stop there as well, so the rest layout would buy a template nothing, and lines broken again at the instants they overflow would jump from one layout to another during the move, which is no layout. Breaking once at the widest tracking keeps one layout over the whole clip, at a cost: the settled title keeps the breaks of its widest instant, and a name that `lines` accepts at rest can stop under a tracking-in entrance.

Tracking after the last character of a line, as CSS `letter-spacing` adds it: a centred line would sit half a tracking step to the left of its centre, and a right-aligned one would end short of its edge.

Scripts whose shaping moves glyphs across characters left out, as right-to-left text is: Devanagari and the other Indic scripts run left to right and an NLE titles them, and the groups that merge until they lie in text order give every glyph one character at no cost to the scripts that move none, where each platform's shaper reports reordered glyphs in its own way.

Right-to-left and mixed-direction text is left out (README).
